CATEGORY 01

Berdasarkan Fungsi (Speech Act)

Klasifikasi paling umum dalam ilmu komunikasi: apa yang sebenarnya dilakukan sebuah kalimat — menyatakan, meminta, menolak, mengkritik, dan seterusnya.

Pernyataan

Statement

Tujuan: memberi informasi secara faktual.

1Daily standup — designer melapor status ke PM.
Designer (you)
ENThe onboarding flow is ready for handoff. All five screens are in the "Ready for Dev" section, and the spec includes the empty and error states.
IDFlow onboarding sudah siap untuk handoff. Kelima layar ada di section "Ready for Dev", dan spec-nya sudah termasuk empty state dan error state.
Anuj (PM)
ENGood. So we're on track for the sprint demo on Friday.
IDBagus. Berarti kita masih sesuai jadwal untuk demo sprint hari Jumat.
2Client kickoff — menyampaikan temuan riset awal.
Designer
ENBased on the twelve interviews we ran, users drop off at the account verification step, not at sign-up. That's where 40% of the churn happens.
IDBerdasarkan dua belas wawancara yang kami lakukan, user berhenti di tahap verifikasi akun, bukan di sign-up. Di situlah 40% churn terjadi.
Client
ENThat's surprising. We always assumed sign-up was the problem.
IDItu mengejutkan. Kami selalu mengira sign-up yang jadi masalahnya.
Designer
ENThe data points elsewhere. I'll share the funnel breakdown after this call.
IDDatanya menunjukkan hal lain. Saya akan kirim rincian funnel-nya setelah call ini.
3Design review — menjelaskan keputusan layout.
Designer
ENThe primary action sits at the bottom because the screen is used one-handed on mobile. Everything above the fold is read-only information.
IDTombol aksi utama diletakkan di bawah karena layar ini dipakai satu tangan di mobile. Semua yang di atas lipatan hanya informasi read-only.
Martha (Design peer)
ENMakes sense. That matches the thumb-reach zone we defined in the system.
IDMasuk akal. Itu sesuai dengan zona jangkauan jempol yang kita tetapkan di design system.
4Handoff ke engineer — menyampaikan spec token.
Designer
ENAll spacing uses the 4-point grid. The card padding is 16, and the gap between cards is 12 — those map to spacing tokens, not hard-coded values.
IDSemua spacing memakai grid 4-point. Padding card-nya 16, dan jarak antar card 12 — itu semua mengacu ke spacing token, bukan nilai hard-coded.
Bhaveen (Engineer)
ENUnderstood. I'll pull the token names straight from the library so nothing drifts.
IDPaham. Saya akan ambil nama token langsung dari library supaya tidak ada yang meleset.
5Stakeholder sync — melaporkan hasil A/B test.
Designer
ENThe new checkout variant increased completion by 8.3% over two weeks. The result is statistically significant, so we can safely ship it to everyone.
IDVarian checkout baru menaikkan penyelesaian sebesar 8,3% selama dua minggu. Hasilnya signifikan secara statistik, jadi kita aman untuk merilisnya ke semua user.
Avril (Stakeholder)
ENStrong number. Let's document it as the new baseline.
IDAngka yang kuat. Mari kita catat sebagai baseline yang baru.

Pertanyaan

Question

Tujuan: meminta informasi.

1Requirement gathering dengan PM.
Designer
ENBefore I start wireframing — what's the single most important action a user should take on this screen?
IDSebelum saya mulai wireframe — apa satu aksi paling penting yang harus dilakukan user di layar ini?
Anuj (PM)
ENDeposit funds. Everything else is secondary.
IDMenyetor dana. Selebihnya sekunder.
2Klarifikasi constraint teknis ke engineer.
Designer
ENIs real-time price updating feasible on this screen, or will there be a delay we need to design around?
IDApakah update harga real-time memungkinkan di layar ini, atau akan ada jeda yang perlu kita antisipasi lewat desain?
Bhaveen (Engineer)
ENThere's a two-to-three second delay from the market feed. We should show a "last updated" timestamp.
IDAda jeda dua sampai tiga detik dari feed pasar. Sebaiknya kita tampilkan timestamp "terakhir diperbarui".
Designer
ENGot it — then a subtle refresh indicator is better than pretending it's instant.
IDOke — berarti indikator refresh yang halus lebih baik daripada berpura-pura harganya instan.
3Usability test — menggali perilaku user.
Designer (moderator)
ENWhen you landed on this screen, what did you expect to happen after tapping "Continue"?
IDKetika Anda sampai di layar ini, apa yang Anda harapkan terjadi setelah menekan "Lanjutkan"?
Participant
ENHonestly, I expected a confirmation, not another form.
IDJujur, saya mengharapkan konfirmasi, bukan formulir lagi.
4Scoping meeting — menanyakan prioritas ke client.
Designer
ENIf we can only ship one of these two features this quarter, which one moves the needle more for your business?
IDKalau kuartal ini kita hanya bisa merilis salah satu dari dua fitur ini, yang mana yang lebih berdampak untuk bisnis Anda?
Client
ENThe referral program. It ties directly to our growth target.
IDProgram referral. Itu terkait langsung dengan target pertumbuhan kami.
5Design critique — bertanya soal rasionalisasi rekan.
Designer
ENWhat made you choose a bottom sheet here instead of a full page? I want to understand the trade-off.
IDApa yang membuatmu memilih bottom sheet di sini alih-alih full page? Aku ingin memahami trade-off-nya.
Iksan (Designer)
ENThe task is quick, so I wanted to keep the user in context instead of navigating away.
IDTugasnya cepat, jadi aku ingin menjaga user tetap dalam konteks daripada berpindah halaman.

Perintah

Command

Tujuan: meminta tindakan (langsung, biasanya ke tim sendiri / bawahan).

1Lead designer mengarahkan sebelum client review.
Designer (lead)
ENExport the final frames to PDF and drop them in the shared folder before 3 PM — the client review is at 4.
IDTolong ekspor frame final ke PDF dan taruh di folder bersama sebelum jam 3 — review dengan client jam 4.
Iksan (Junior designer)
ENOn it. I'll ping you once it's uploaded.
IDSiap. Aku kabari begitu sudah terunggah.
2QA handoff — instruksi verifikasi bug.
Designer
ENPlease re-test the watchlist screen on the smallest device size and confirm the padding bug is gone before you close the ticket.
IDTolong tes ulang layar watchlist di ukuran perangkat terkecil dan pastikan bug padding-nya sudah hilang sebelum menutup tiket.
Moeez (QA)
ENWill do. I'll attach a screenshot as evidence.
IDBaik. Aku lampirkan screenshot sebagai bukti.
3Krisis produksi — arahan cepat.
Designer
ENRevert the button color to the previous token right now — the new one fails contrast and it's live.
IDKembalikan warna tombol ke token sebelumnya sekarang juga — yang baru gagal kontras dan sudah tayang.
Bhaveen (Engineer)
ENReverting now. Fix will be live in five minutes.
IDSedang dikembalikan. Perbaikannya tayang dalam lima menit.
4Workshop — mengarahkan aktivitas peserta.
Designer (facilitator)
ENWrite one pain point per sticky note, and put them all on the left wall. Don't group them yet.
IDTulis satu pain point per sticky note, dan tempel semuanya di dinding kiri. Jangan dikelompokkan dulu.
Anjum (Participant)
ENGot it — one idea per note.
IDPaham — satu ide per catatan.
5Menjaga konsistensi file — instruksi ke tim.
Designer
ENName every new component using the "category / name / state" convention. Anything off-pattern gets rejected in review.
IDBeri nama setiap komponen baru dengan konvensi "kategori / nama / state". Apa pun yang menyimpang dari pola akan ditolak saat review.
Inas (Designer)
ENUnderstood. I'll rename the ones I added yesterday.
IDPaham. Aku akan ganti nama yang kutambahkan kemarin.

Permintaan

Request

Tujuan: meminta bantuan secara sopan (biasanya lintas fungsi / setara).

1Minta review ke rekan desain.
Designer
ENWould you have twenty minutes to review my transfer flow? I'd love a second pair of eyes before handoff.
IDApakah kamu punya waktu dua puluh menit untuk mereview flow transfer-ku? Aku ingin ada pandangan kedua sebelum handoff.
Martha (Designer)
ENOf course. Send me the link and I'll leave comments this afternoon.
IDTentu. Kirim link-nya, nanti sore aku beri komentar.
2Minta data ke analyst.
Designer
ENCould you help me pull the drop-off rate for each step of the KYC flow? I want to prioritize the right screen to redesign.
IDBisakah kamu bantu ambilkan tingkat drop-off untuk tiap langkah di flow KYC? Aku ingin memprioritaskan layar yang tepat untuk didesain ulang.
Janusz (Data)
ENHappy to. I'll have the breakdown for you by tomorrow morning.
IDDengan senang hati. Rinciannya kukirim besok pagi.
3Minta perpanjangan waktu ke PM.
Designer
ENCould I ask for one extra day on the dashboard? The data-heavy states need more testing to get right.
IDBolehkah saya minta tambahan satu hari untuk dashboard-nya? State yang padat data butuh lebih banyak pengujian agar benar.
Anuj (PM)
ENOne day is fine, as long as the handoff still lands before the sprint closes.
IDSatu hari tidak masalah, asalkan handoff tetap masuk sebelum sprint berakhir.
4Minta akses ke stakeholder client.
Designer
ENWould it be possible to speak with two of your support agents? They see user problems firsthand, and that would sharpen the redesign.
IDApakah memungkinkan untuk berbicara dengan dua agen support Anda? Mereka melihat masalah user secara langsung, dan itu akan mempertajam desain ulang kami.
Client
ENSure — I'll connect you with the support lead this week.
IDTentu — akan saya hubungkan dengan lead support minggu ini.
5Minta engineer memeriksa kelayakan animasi.
Designer
ENWhen you get a chance, could you check whether this chart animation is realistic on low-end devices? I'd rather cut it than ship something janky.
IDKalau sempat, bisakah kamu cek apakah animasi chart ini realistis di perangkat kelas bawah? Aku lebih baik memotongnya daripada merilis sesuatu yang tersendat.
Tobi (Engineer)
ENI'll prototype it on a test device and let you know the frame rate.
IDAku akan buat prototipenya di perangkat uji dan kabari frame rate-nya.

Larangan

Prohibition

Tujuan: melarang sebuah tindakan.

1Menjaga integritas design system.
Designer (system owner)
ENPlease don't detach components from the library. If something's missing, tell me and I'll add the variant — detaching breaks updates for everyone.
IDTolong jangan detach komponen dari library. Kalau ada yang kurang, beri tahu aku dan akan kutambahkan varian-nya — detach merusak update untuk semua orang.
Inas (Designer)
ENFair point. I'll request the variant instead.
IDSetuju. Aku akan minta varian-nya saja.
2Menahan perubahan menjelang rilis.
Designer
ENLet's not change the copy after code freeze. Any wording edits should wait for the next release, or we risk introducing bugs.
IDMari kita tidak mengubah copy setelah code freeze. Semua perubahan wording sebaiknya menunggu rilis berikutnya, atau kita berisiko memunculkan bug.
Anuj (PM)
ENAgreed. I'll hold the marketing team's request until then.
IDSetuju. Aku akan menahan permintaan tim marketing sampai saat itu.
3Menjaga privasi data saat riset.
Designer
ENPlease don't record any real account numbers during the sessions. Use the dummy data we prepared — real details can't leave the room.
IDTolong jangan merekam nomor rekening asli selama sesi berlangsung. Gunakan data dummy yang sudah kita siapkan — detail asli tidak boleh keluar dari ruangan.
Moeez (Note-taker)
ENNoted. I'll mask anything sensitive in the notes.
IDDicatat. Aku akan menyamarkan apa pun yang sensitif di catatan.
4Menegakkan aturan aksesibilitas.
Designer
ENWe can't use color alone to signal errors. Every error state needs an icon and text too, otherwise colorblind users are left guessing.
IDKita tidak boleh menggunakan warna saja untuk menandakan error. Setiap error state butuh ikon dan teks juga, kalau tidak user buta warna akan menebak-nebak.
Iksan (Designer)
ENRight. I'll add an inline message under each field.
IDBenar. Aku akan menambahkan pesan inline di bawah tiap field.
5Melarang scope creep dari client secara sopan.
Client
ENCan we also add a chat feature into this same release?
IDBisakah kita juga menambahkan fitur chat ke rilis yang sama ini?
Designer
ENI'd advise against adding it to this release. Squeezing it in now would put the launch date at risk — let's scope it properly as a fast-follow.
IDSaya menyarankan untuk tidak menambahkannya ke rilis ini. Memaksakannya sekarang akan membahayakan tanggal peluncuran — mari kita rencanakan dengan benar sebagai fast-follow.

Saran

Suggestion

Tujuan: memberi alternatif.

1Review flow yang terlalu panjang.
Designer
ENWe could combine the last two steps into one screen. It would cut the flow from five taps to three without losing any information.
IDKita bisa menggabungkan dua langkah terakhir jadi satu layar. Itu akan memotong flow dari lima tap jadi tiga tanpa kehilangan informasi apa pun.
Anuj (PM)
ENI like that. Let's prototype the shorter version and test both.
IDAku suka itu. Mari kita buat prototipe versi lebih pendek dan tes keduanya.
2Menawarkan pendekatan riset yang lebih hemat.
Designer
ENInstead of a full study, we might run a quick unmoderated test with five users. We'd get directional answers by Thursday.
IDAlih-alih studi penuh, kita bisa menjalankan tes unmoderated singkat dengan lima user. Kita akan dapat jawaban arah pada hari Kamis.
Client
ENThat works better for our timeline. Let's do that.
IDItu lebih cocok untuk timeline kami. Mari lakukan itu.
3Alternatif solusi teknis dengan engineer.
Bhaveen (Engineer)
ENThis gradient is expensive to render on scroll.
IDGradient ini berat untuk di-render saat scroll.
Designer
ENThen let's use a static gradient image behind the header. Visually it's identical and it won't cost you performance.
IDKalau begitu, mari pakai gambar gradient statis di belakang header. Secara visual identik dan tidak membebani performa.
4Menyarankan penamaan yang lebih jelas untuk copy.
Designer
ENRather than "Submit," I'd suggest "Confirm transfer." It tells the user exactly what happens next.
IDDaripada "Submit", saya sarankan "Konfirmasi transfer". Itu memberi tahu user persis apa yang akan terjadi berikutnya.
Inas (Content designer)
ENAgreed — action-specific labels always test better.
IDSetuju — label yang spesifik pada aksi selalu lebih baik saat diuji.
5Menawarkan cara membagi pekerjaan.
Designer
ENWe could split the work — I take the trading screens, you take onboarding. That way we both hit the deadline.
IDKita bisa membagi pekerjaan — aku ambil layar trading, kamu ambil onboarding. Dengan begitu kita berdua bisa mengejar deadline.
Martha (Designer)
ENGood split. Let's sync every morning to stay aligned.
IDPembagian yang bagus. Mari sync tiap pagi supaya tetap sejalan.

Nasihat

Advice

Tujuan: memberi arahan / bimbingan (biasanya ke orang, bukan ke solusi).

1Mentoring junior designer soal portfolio.
Designer (senior)
ENYou should lead your case study with the problem and the outcome, not the final screens. Recruiters want to see how you think.
IDSebaiknya kamu memulai case study dengan masalah dan hasilnya, bukan layar finalnya. Recruiter ingin melihat cara berpikirmu.
Iksan (Junior)
ENThat makes sense. I'll restructure it around the story.
IDMasuk akal. Aku akan menyusun ulang berdasarkan alur ceritanya.
2Menasihati rekan yang kewalahan.
Inas (Designer)
ENI've been redesigning this all weekend and I'm still not happy with it.
IDAku sudah mendesain ulang ini sepanjang akhir pekan dan masih belum puas.
Designer
ENYou should step away and get feedback before polishing more. Fresh eyes will save you hours of second-guessing.
IDSebaiknya kamu berhenti dulu dan minta feedback sebelum memoles lagi. Pandangan segar akan menghemat berjam-jam keraguanmu.
3Menasihati client soal ekspektasi peluncuran.
Designer
ENMy advice would be to launch to a small group first. You'll catch real issues before they hit your whole user base.
IDSaran saya, luncurkan ke kelompok kecil dulu. Anda akan menangkap masalah nyata sebelum menyentuh seluruh basis user.
Client
ENA phased rollout — that's sensible. Let's plan it that way.
IDPeluncuran bertahap — itu bijaksana. Mari rencanakan seperti itu.
4Menasihati soal keterlibatan lintas fungsi.
Designer (lead)
ENYou'd be better off looping in engineering early. Involving them at the wireframe stage prevents rework later.
IDKamu akan lebih baik melibatkan engineering sejak awal. Mengikutsertakan mereka di tahap wireframe mencegah pengerjaan ulang nanti.
Iksan (Designer)
ENNoted. I'll invite Tobi to the next design sync.
IDDicatat. Aku akan mengundang Tobi ke design sync berikutnya.
5Menasihati soal istirahat / burnout.
Designer
ENYou've been pushing hard for three sprints straight. Take the afternoon off — the work will be better for it, and so will you.
IDKamu sudah bekerja keras tiga sprint berturut-turut. Ambil libur sore ini — hasil kerjanya akan lebih baik, begitu juga kamu.
Inas (Designer)
ENThanks. I think I do need to reset.
IDTerima kasih. Sepertinya aku memang perlu me-reset.

Ajakan

Invitation

Tujuan: mengajak melakukan sesuatu bersama.

1Mengajak diskusi menyelesaikan perdebatan desain.
Designer
ENLet's jump on a quick call to settle the navigation debate. Twenty minutes together beats another day of comment threads.
IDAyo kita call sebentar untuk menyelesaikan perdebatan navigasi. Dua puluh menit bersama lebih baik daripada satu hari lagi thread komentar.
Iksan (Designer)
ENAgreed. I'll set up a room now.
IDSetuju. Aku buatkan ruangannya sekarang.
2Mengajak stakeholder ke sesi riset.
Designer
ENWe'd love for you to observe the usability sessions on Wednesday. Hearing users struggle firsthand is more convincing than any report.
IDKami ingin mengundang Anda mengamati sesi usability hari Rabu. Mendengar langsung user kesulitan lebih meyakinkan daripada laporan apa pun.
Avril (Stakeholder)
ENCount me in. Send the calendar invite.
IDIkut saya. Kirim undangan kalendernya.
3Mengajak engineer co-design.
Designer
ENWant to pair on the error states this afternoon? If we design them together, the handoff practically writes itself.
IDMau pairing untuk error states sore ini? Kalau kita desain bersama, handoff-nya praktis menulis dirinya sendiri.
Tobi (Engineer)
ENSure, I'm free after 2. Let's do it.
IDBoleh, aku senggang setelah jam 2. Ayo.
4Mengajak tim ke design critique.
Designer (lead)
ENLet's start a weekly critique on Fridays. Bring one piece of work in progress — messy is welcome.
IDMari kita mulai critique mingguan tiap Jumat. Bawa satu karya yang sedang berjalan — yang berantakan pun dipersilakan.
Martha (Designer)
ENLove it. Regular critique will lift the whole team.
IDSuka sekali. Critique rutin akan mengangkat seluruh tim.
5Mengajak client workshop co-creation.
Designer
ENLet's run a half-day workshop with your team to map the ideal journey together. You know your customers better than anyone.
IDAyo kita adakan workshop setengah hari bersama tim Anda untuk memetakan perjalanan ideal bersama-sama. Anda mengenal pelanggan lebih dari siapa pun.
Client
ENWe'd value that. Let's find a date next week.
IDKami menghargai itu. Mari cari tanggal minggu depan.

Offer

Tujuan: menawarkan bantuan.

1Menawarkan bantuan ke PM yang kewalahan.
Designer
ENI can put together the flow diagram for the spec if that takes something off your plate before the review.
IDSaya bisa menyusun diagram flow untuk spec-nya kalau itu meringankan beban Anda sebelum review.
Anuj (PM)
ENThat would help a lot, thank you.
IDItu sangat membantu, terima kasih.
2Menawarkan aset ke engineer.
Designer
ENI can export all the icons as SVGs and name them to match your components, so you don't have to slice anything.
IDAku bisa mengekspor semua ikon sebagai SVG dan memberi nama sesuai komponenmu, jadi kamu tidak perlu memotong apa pun.
Tobi (Engineer)
ENThat saves me real time. Much appreciated.
IDItu menghemat waktuku. Sangat kuhargai.
3Menawarkan mentoring ke junior.
Designer (senior)
ENIf you'd like, I can walk you through how I set up auto layout for this card. Happy to screen-share whenever you're stuck.
IDKalau kamu mau, aku bisa memandumu cara mengatur auto layout untuk card ini. Dengan senang hati screen-share kapan pun kamu buntu.
Iksan (Junior)
ENYes please — auto layout still trips me up.
IDIya boleh — auto layout masih bikin aku bingung.

Client

IDSaya khawatir user kami yang lebih tua tidak akan memahami layout baru ini.
Designer
ENWe can test it specifically with that age group before launch. I'll set up five sessions and bring you the findings.
IDKami bisa mengujinya khusus dengan kelompok usia itu sebelum peluncuran. Saya akan mengatur lima sesi dan membawakan temuannya.
5Menawarkan menutup sesi presentasi.
Designer
ENI can prepare a one-page summary of today's decisions and circulate it, so everyone leaves aligned.
IDSaya bisa menyiapkan ringkasan satu halaman berisi keputusan hari ini dan menyebarkannya, agar semua orang pulang dengan pemahaman yang sama.
Avril (Stakeholder)
ENPlease do — that will keep us all honest.
IDSilakan — itu akan menjaga kita semua konsisten.

Persetujuan

Agreement

Tujuan: menyetujui.

1Menyetujui arah desain di review.
Anuj (PM)
ENI think the simpler card layout is the right call.
IDMenurutku layout card yang lebih sederhana adalah keputusan yang tepat.
Designer
ENI agree completely. It's cleaner and it maps to the data users actually scan for.
IDSaya sepenuhnya setuju. Lebih bersih dan sesuai dengan data yang benar-benar dicari user.
2Menerima kompromi dengan engineer.
Tobi (Engineer)
ENWe can do the animation, but only on the summary card, not the whole list.
IDKita bisa membuat animasinya, tapi hanya di card ringkasan, bukan seluruh list.
Designer
ENThat's a fair compromise. The summary card is where it matters most anyway.
IDItu kompromi yang adil. Toh card ringkasan yang paling penting.
3Menyetujui prioritas client.
Client
ENLet's prioritize accessibility over the visual polish for this release.
IDMari kita prioritaskan aksesibilitas di atas poles visual untuk rilis ini.
Designer
ENAbsolutely, I'm with you on that. Accessible now, beautiful next — both matter, but that's the right order.
IDTentu, saya sepakat. Aksesibel dulu, indah kemudian — keduanya penting, tapi itu urutan yang tepat.
4Menyetujui feedback critique.
Martha (Designer)
ENThe heading hierarchy feels flat — the page title and section titles look the same weight.
IDHierarki heading-nya terasa datar — judul halaman dan judul section tampak sebobot.
Designer
ENYou're right. I'll bump the page title up a size and lighten the section labels.
IDKamu benar. Aku akan menaikkan ukuran judul halaman dan meringankan label section.
5Menyetujui rencana rilis bertahap.
Anuj (PM)
ENSo we're aligned — 10% rollout first, then 50%, then full.
IDJadi kita sepakat — rollout 10% dulu, lalu 50%, kemudian penuh.
Designer
ENAgreed. I'll prepare the design QA checklist for each stage.
IDSetuju. Saya akan menyiapkan checklist design QA untuk tiap tahap.

Penolakan

Disagreement / Rejection

Tujuan: menyatakan tidak setuju (secara diplomatis, disertai alasan).

1Menolak permintaan menambah tombol.
Client
ENCan we add a second call-to-action button next to the main one?
IDBisakah kita menambahkan tombol call-to-action kedua di samping yang utama?
Designer
ENI'd push back on that. Two competing buttons split the user's attention and usually lower conversion on both. I'd keep one clear primary action.
IDSaya kurang sepakat. Dua tombol yang bersaing memecah perhatian user dan biasanya menurunkan konversi keduanya. Saya akan mempertahankan satu aksi utama yang jelas.
2Tidak setuju dengan estimasi PM.
Anuj (PM)
ENDesign for this should take two days, right?
IDDesain untuk ini seharusnya dua hari, kan?
Designer

IDBisa. Dashboard dulu, draf profil kedua.

IDAyo cari versi yang cocok untuk kita berdua. Kita bisa mencapai akhir bulan kalau dibuat bertahap — flow inti dulu, layar sekunder dua minggu kemudian. Anda tetap rilis tepat waktu dengan hal-hal esensialnya.

IDSaya bisa memberi dua dari tiga hari itu dengan memangkas kerja animasi, tapi saya ingin mempertahankan hari terakhir untuk pengecekan aksesibilitas. Itu yang tidak akan saya tukar.

CATEGORY 05

Berdasarkan Bentuk Pertanyaan

Cara bertanya menentukan jenis jawaban yang didapat: ya/tidak, terbuka, tertutup, retoris, klarifikasi, probing, leading, hipotetis, reflektif, konfirmasi. Designer yang baik memilih bentuk pertanyaan secara sadar.

Ya / Tidak

Yes/No Question

Tujuan: mendapat keputusan atau konfirmasi cepat.

1Konfirmasi cepat sebelum handoff.
Designer (you)
ENIs the API contract for the balance endpoint final?
IDApakah kontrak API untuk endpoint saldo sudah final?
Bhaveen (Engineer)
ENYes, locked as of yesterday. You can design against it.
IDYa, sudah dikunci sejak kemarin. Kamu bisa mendesain berdasarkan itu.
2Meminta keputusan dari PM.
Designer
ENAre we including dark mode in this release, yes or no?
IDApakah kita memasukkan dark mode di rilis ini, ya atau tidak?
Anuj (PM)
ENNo — we'll defer it to the next cycle.
IDTidak — kita tunda ke siklus berikutnya.
3Konfirmasi persetujuan client.
Designer
ENAre you happy to sign off on this direction so we can start building?
IDApakah Anda setuju menyetujui arah ini supaya kami bisa mulai membangun?
Client
ENYes, you have my approval. Go ahead.
IDYa, Anda punya persetujuan saya. Silakan lanjut.
4Cek ketersediaan rekan.
Designer
ENCan you review my prototype before three today?
IDBisakah kamu review prototipe saya sebelum jam tiga hari ini?
Iksan (Designer)
ENYes, send it over — I'll get to it after lunch.
IDYa, kirim saja — saya kerjakan setelah makan siang.
5Verifikasi cakupan QA.
Designer
ENDid the error states get tested on the small breakpoint?
IDApakah error state-nya sudah dites di breakpoint kecil?
Moeez (QA)
ENNot yet — that's on my list for this afternoon.
IDBelum — itu ada di daftar saya untuk sore ini.

ENTell me what was going through your mind when you paused on that screen.
IDCeritakan apa yang ada di pikiran Anda saat berhenti di layar itu.
Participant

IDSaya tidak yakin apakah transfernya benar-benar berhasil atau tidak.
3Membuka diskusi arah desain dengan tim.

IDBagaimana kita bisa membuat ini terasa lebih seperti percakapan dan bukan formulir?

IDMungkin satu pertanyaan per layar, dengan nada ramah di copy-nya.

IDKekhawatiran apa yang Anda miliki yang belum kita bahas?

IDSebaiknya saya pakai modal atau full screen di sini?

IDApa yang diminta task ini dari user, dan seberapa banyak fokus yang dibutuhkan? Mulai dari situ dan ceritakan kesimpulanmu.

Klarifikasi

Clarifying

Tujuan: memastikan pemahaman yang benar sebelum bertindak.

1Memastikan maksud feedback client.
Client
ENMake the dashboard cleaner.
IDBuat dashboard-nya lebih bersih.
Designer (you)
ENWhen you say cleaner — do you mean fewer elements on screen, or more spacing between the ones we keep?
IDKetika Anda bilang lebih bersih — maksudnya lebih sedikit elemen di layar, atau lebih banyak jarak antara yang kita pertahankan?
2Klarifikasi requirement teknis.
Bhaveen (Engineer)
ENThe list should update in real time.
IDDaftarnya harus update secara real time.
Designer
ENJust to be clear — real time as in the moment data changes, or refreshed each time the user opens the screen?
IDSupaya jelas — real time dalam arti saat data berubah, atau di-refresh setiap kali user membuka layar?
3Klarifikasi scope dari PM.
Anuj (PM)
ENWe need the onboarding done.
IDKita butuh onboarding-nya selesai.
Designer
ENDoes "done" include the edge cases — no network, expired session — or just the happy path for the demo?
IDApakah "selesai" termasuk edge case — tanpa jaringan, sesi kedaluwarsa — atau hanya happy path untuk demo?
4Klarifikasi istilah yang ambigu.
Avril (Stakeholder)
ENLet's make it more premium.
IDAyo buat lebih premium.
Designer
ENCan you help me pin that down? Premium could mean darker tones, more whitespace, or richer motion. Which feels closest to what you picture?
IDBisakah Anda membantu memperjelasnya? Premium bisa berarti nada lebih gelap, lebih banyak ruang kosong, atau gerak yang lebih kaya. Mana yang paling dekat dengan yang Anda bayangkan?
5Klarifikasi prioritas revisi.

CATEGORY 10

Berdasarkan Strategi Retorika

Teknik menyusun pesan agar meyakinkan: menjelaskan, membandingkan, menganalogikan, bercerita, memberi contoh, menyimpulkan, menekankan, mengulang, mengutip, mengajukan argumen, memberi bukti, membantah argumen. Ini adalah perkakas komunikasi seorang desainer.

Menjelaskan

Explain

Tujuan: membuat sesuatu yang rumit menjadi mudah dipahami.

1Menjelaskan design token ke client.
Client
ENWhy does changing one color take so long?
IDKenapa mengubah satu warna butuh waktu lama?
Designer (you)
ENHere's how it works: that one color is a token used on 42 screens. Change the token once and it updates everywhere — but we still test all 42 so nothing breaks. That testing is the time.
IDBegini cara kerjanya: warna itu adalah token yang dipakai di 42 layar. Ubah token sekali dan ia berubah di mana-mana — tapi kita tetap menguji ke-42 layarnya agar tidak ada yang rusak. Pengujian itulah yang memakan waktu.
2Menjelaskan alasan sebuah keputusan.
Anuj (PM)
ENWhy put the balance at the top and not the transactions?
IDKenapa saldo ditaruh di atas, bukan transaksi?
Designer
ENThe reason is that "how much do I have" is the first question almost everyone opens the app to answer. We put the most-asked question where the eye lands first.
IDAlasannya, "berapa uang saya" adalah pertanyaan pertama yang hampir semua orang cari saat membuka aplikasi. Kita taruh pertanyaan yang paling sering ditanya di tempat mata pertama kali jatuh.
3Menjelaskan proses ke stakeholder baru.
Avril (Stakeholder)
ENWalk me through how you get from idea to final screen.
IDJelaskan ke saya bagaimana Anda beranjak dari ide ke layar final.
Designer
ENIn short: we sketch rough structure first, test it with users, then add visual polish only once the flow is proven. We solve the hard problems before making it pretty.
IDSingkatnya: kami menyketsa struktur kasar dulu, mengujinya dengan user, lalu menambahkan poles visual hanya setelah flow-nya terbukti. Kami menyelesaikan masalah sulit sebelum mempercantik.
4Menjelaskan istilah ke junior.
Inas (Junior Designer)
ENWhat's the difference between affordance and signifier?
IDApa bedanya affordance dan signifier?
Designer
ENThink of it this way: the affordance is what a button can do — it can be pressed. The signifier is the visual clue that tells you so — the shadow that makes it look pressable.
IDBayangkan begini: affordance adalah apa yang bisa dilakukan tombol — ia bisa ditekan. Signifier adalah petunjuk visual yang memberi tahumu itu — bayangan yang membuatnya tampak bisa ditekan.
5Menjelaskan trade-off ke engineer.
Bhaveen (Engineer)
ENWhy not just load everything at once?
IDKenapa tidak muat semuanya sekaligus saja?
Designer
ENBecause the user only sees the first screen's worth at once. Loading the rest as they scroll means the first paint is fast — the perceived speed is what they feel, not the total.
IDKarena user hanya melihat sebanyak satu layar sekaligus. Memuat sisanya saat mereka scroll membuat tampilan pertama cepat — kecepatan yang dirasakan itulah yang mereka rasakan, bukan totalnya.

Membandingkan

Compare

Tujuan: memperjelas pilihan dengan menaruh opsi berdampingan.

1Membandingkan dua layout untuk client.
Designer (you)
ENLet's compare them side by side. Option A shows more at once but feels dense; Option B shows less but is calmer and faster to scan. Density versus clarity.
IDAyo bandingkan berdampingan. Opsi A menampilkan lebih banyak sekaligus tapi terasa padat; Opsi B menampilkan lebih sedikit tapi lebih tenang dan cepat dipindai. Kepadatan lawan kejelasan.
Client
ENPut that way, B fits our audience better.
IDDijelaskan begitu, B lebih cocok untuk audiens kami.
2Membandingkan dengan kompetitor.
Avril (Stakeholder)
ENHow do we stack up against the market leader?
IDBagaimana posisi kita dibanding pemimpin pasar?
Designer
ENThey win on breadth — more features on screen. We win on focus — a first-timer completes a transfer faster with us. We're not louder; we're clearer.
IDMereka unggul di keluasan — lebih banyak fitur di layar. Kita unggul di fokus — pengguna baru menyelesaikan transfer lebih cepat dengan kita. Kita bukan lebih ramai; kita lebih jelas.
3Membandingkan sebelum-sesudah.
Designer
ENCompare the old flow to the new: five steps became three, and the confusing mid-step is gone. Same task, less effort.
IDBandingkan flow lama dengan yang baru: lima langkah menjadi tiga, dan langkah tengah yang membingungkan hilang. Tugas yang sama, usaha yang lebih sedikit.
Anuj (PM)
ENThe contrast makes the value obvious.
IDKontrasnya membuat nilainya jelas.
4Membandingkan trade-off teknis.
Bhaveen (Engineer)
ENNative component or custom one?
IDKomponen native atau kustom?
Designer
ENNative is faster to build and more reliable but less distinctive; custom is on-brand but slower and higher-maintenance. For this screen, I'd trade distinctiveness for reliability.
IDNative lebih cepat dibangun dan lebih andal tapi kurang khas; kustom sesuai merek tapi lebih lambat dan lebih tinggi perawatannya. Untuk layar ini, saya akan menukar kekhasan demi keandalan.
5Membandingkan biaya vs manfaat.
Designer
ENCompare the cost of a one-week test to the cost of building the wrong thing for a month. One week now versus four weeks of rework — the choice makes itself.
IDBandingkan biaya tes satu minggu dengan biaya membangun hal yang salah selama sebulan. Satu minggu sekarang lawan empat minggu rework — pilihannya jelas dengan sendirinya.
Avril (Stakeholder)
ENFair. Let's do the week.
IDMasuk akal. Ayo ambil satu minggunya.

Menganalogikan

Analogy / Metaphor

Tujuan: menjelaskan konsep asing lewat sesuatu yang sudah dikenal.

1Analogi untuk design system.
Client
ENWhy invest in a design system upfront?
IDKenapa berinvestasi di design system di awal?
Designer (you)
ENThink of it like LEGO bricks. Making the bricks takes effort once, but after that every new build snaps together fast — instead of carving each piece from scratch every time.
IDAnggap seperti balok LEGO. Membuat baloknya butuh usaha sekali, tapi setelah itu setiap bangunan baru tersusun cepat — alih-alih memahat tiap potongan dari nol setiap kali.
2Analogi untuk whitespace.
Avril (Stakeholder)
ENAll that empty space feels like wasted screen.
IDSemua ruang kosong itu terasa seperti layar yang terbuang.
Designer
ENWhitespace is like the silence between notes in music. Take it away and you don't get more music — you get noise. The space is what lets the content breathe.
IDWhitespace itu seperti keheningan di antara nada dalam musik. Hilangkan, dan kamu tidak dapat lebih banyak musik — kamu dapat kebisingan. Ruang itulah yang membuat konten bernapas.
3Analogi untuk technical debt.
Anuj (PM)
ENCan't the cleanup wait?
IDTidak bisakah pembersihannya menunggu?
Designer
ENDesign debt is like a messy kitchen. You can keep cooking around the clutter for a while, but every meal gets slower until eventually you can't move. Cleaning now keeps us fast.
IDUtang desain itu seperti dapur yang berantakan. Kamu bisa terus memasak di sela kekacauan untuk sementara, tapi tiap masakan makin lambat sampai akhirnya tak bisa bergerak. Membersihkan sekarang menjaga kita tetap cepat.
4Analogi untuk progressive disclosure.
Client
ENWhy hide the advanced options?
IDKenapa menyembunyikan opsi lanjutan?
Designer
ENIt's like a good menu at a restaurant. The specials are up front; the full wine list is there if you ask. Everything's available — you're just not handed all of it at once.
IDIni seperti menu yang baik di restoran. Menu andalan di depan; daftar wine lengkap ada kalau kamu minta. Semuanya tersedia — kamu cuma tidak diberi semuanya sekaligus.
5Analogi untuk konsistensi.
Inas (Junior Designer)
ENDoes it really matter if buttons look slightly different?
IDApakah benar-benar penting kalau tombol tampak sedikit berbeda?
Designer
ENConsistency is like a person's handwriting. When it stays the same, you trust it's them. When it changes page to page, you start to wonder if something's off — even if you can't say why.
IDKonsistensi itu seperti tulisan tangan seseorang. Saat tetap sama, kamu percaya itu mereka. Saat berubah dari halaman ke halaman, kamu mulai curiga ada yang salah — meski tak bisa menyebut kenapa.

Memberi contoh

Give Example

Tujuan: menguatkan poin abstrak dengan kasus konkret.

1Contoh konkret untuk konsep abstrak.
Client
ENWhat do you mean by "reducing cognitive load"?
IDApa maksud Anda "mengurangi beban kognitif"?
Designer (you)
ENFor example: instead of asking for the full card number, expiry, and CVV on one screen, we ask one at a time. Same information, but the user only holds one thing in their head at once.
IDContohnya: alih-alih meminta nomor kartu penuh, kedaluwarsa, dan CVV di satu layar, kami meminta satu per satu. Informasi yang sama, tapi user hanya menahan satu hal di kepala sekaligus.
2Contoh dari produk lain.
Anuj (PM)
ENWill users really understand a swipe action?
IDApakah user benar-benar akan paham aksi geser?
Designer
ENThey already do — take email apps, where you swipe to archive. It's a pattern people use daily, so we're borrowing a habit, not teaching a new one.
IDMereka sudah paham — ambil contoh aplikasi email, di mana kamu geser untuk mengarsip. Ini pola yang dipakai orang setiap hari, jadi kita meminjam kebiasaan, bukan mengajarkan yang baru.
3Contoh edge case ke engineer.
Bhaveen (Engineer)
ENWhy design a state for a really long name?
IDKenapa mendesain state untuk nama yang sangat panjang?
Designer
ENBecause real names break layouts. For instance, a user named "Abdul Rahman bin Mohammed Al-Farsi" will overflow the card unless we plan for it. Edge cases are just users we forgot.
IDKarena nama nyata merusak layout. Misalnya, user bernama "Abdul Rahman bin Mohammed Al-Farsi" akan melimpah dari kartu kecuali kita merencanakannya. Edge case hanyalah user yang kita lupakan.
4Contoh untuk membenarkan microcopy.
Avril (Stakeholder)
ENDoes the wording of an error really matter that much?
IDApakah kata-kata sebuah error benar-benar sepenting itu?
Designer
ENHugely. Compare "Error 402" with "Your card was declined — try another." The first makes users call support; the second lets them fix it themselves. Same failure, very different outcome.
IDSangat. Bandingkan "Error 402" dengan "Kartu Anda ditolak — coba yang lain." Yang pertama membuat user menelepon support; yang kedua membiarkan mereka memperbaikinya sendiri. Kegagalan sama, hasil sangat berbeda.
5Contoh untuk mengajari junior.
Inas (Junior Designer)
ENWhat makes a good empty state?
IDApa yang membuat empty state yang baik?
Designer
ENTake the watchlist. A bad one says "No items." A good one says "Track a stock to see it here" with a button to add one. It turns a dead end into a first step.
IDAmbil watchlist. Yang buruk berkata "Tidak ada item." Yang baik berkata "Pantau saham untuk melihatnya di sini" dengan tombol untuk menambah. Itu mengubah jalan buntu menjadi langkah pertama.

ENThat's everything. Clear.
IDItu semuanya. Jelas.

IDBeri saya inti utama dari studinya.

ENIn one line: users trust us with their money but not with their time. Speed, not features, is our biggest opportunity. Everything else supports that.
IDDalam satu baris: user memercayai kami dengan uang mereka tapi tidak dengan waktu mereka. Kecepatan, bukan fitur, adalah peluang terbesar kita. Semua yang lain mendukung itu.
3Menyimpulkan feedback client.

IDJadi untuk memastikan saya menangkap Anda: nada lebih ringan, headline lebih pendek, dan pertahankan gambarnya. Saya akan merevisi ketiganya dan membiarkan sisanya.

IDBiar saya rangkum. Kita sepakat pada tujuan dan hanya berbeda pada titik masuk. Jadi ayo uji kedua titik masuk dan biar data yang memutuskan. Selesai.

IDDi mana posisi kita, singkatnya?

IDDesain sesuai jalur, satu item aksesibilitas adalah satu-satunya risiko terbuka, dan kita sesuai jadwal untuk handoff Jumat. Hijau, dengan satu hal untuk diperhatikan.

1Argumen untuk investasi riset.
Designer (you)

IDIni argumen saya: rework berbiaya empat kali lipat riset. Kita tidak sanggup menebak salah dalam skala besar. Maka, satu minggu pengujian sekarang adalah jalur yang lebih murah, bukan yang lebih lambat.
Avril (Stakeholder)
ENThe logic holds. Approved.
IDLogikanya konsisten. Disetujui.
2Argumen untuk mempertahankan langkah.
Client
ENConvince me the confirmation step earns its place.
IDYakinkan saya langkah konfirmasi itu layak ada.
Designer
ENMoney moves are irreversible. Irreversible actions need a moment to catch mistakes. A one-tap pause prevents wrong transfers. So the small friction buys large safety — that's the trade I'd defend.
IDPerpindahan uang tak bisa dibatalkan. Aksi yang tak bisa dibatalkan butuh momen menangkap kesalahan. Jeda satu-tap mencegah transfer keliru. Jadi friksi kecil membeli keamanan besar — itulah pertukaran yang saya bela.
3Argumen untuk design system.
Anuj (PM)
ENMake the case for the system investment.
IDSampaikan argumen untuk investasi sistemnya.
Designer
ENWe ship the same components repeatedly. Rebuilding them each time wastes hours and creates inconsistency. A shared system removes both. So it pays for itself in speed and quality together.
IDKita merilis komponen yang sama berulang kali. Membangunnya ulang tiap kali membuang jam dan menciptakan inkonsistensi. Sistem bersama menghapus keduanya. Jadi ia membayar dirinya lewat kecepatan dan kualitas sekaligus.

Client
ENI still want the extra dashboard widgets.
IDSaya tetap ingin widget dashboard tambahan.
Designer
ENConsider the chain: more widgets mean more to scan, more scanning means slower decisions, slower decisions mean the core action gets buried. The feature you'd add weakens the feature you care about most.
IDPertimbangkan rantainya: lebih banyak widget berarti lebih banyak dipindai, lebih banyak pindai berarti keputusan lebih lambat, keputusan lebih lambat berarti aksi inti terkubur. Fitur yang Anda tambahkan melemahkan fitur yang paling Anda pedulikan.

Avril (Stakeholder)

IDKenapa memperlakukan aksesibilitas sebagai tak bisa ditawar?

IDAplikasi perbankan harus melayani setiap nasabah. Sebagian nasabah punya penglihatan rendah atau keterbatasan motorik. Kalau aplikasi mengecualikan mereka, kita gagal pada kewajiban hukum sekaligus bisnis. Akses bukan tambahan — itu dasar melayani semua orang.

Membantah argumen

Refute an Argument

Tujuan: membongkar logika lawan, bukan sekadar menyatakan tidak setuju.

1Membantah dengan menyerang premis.
Client
ENMore features means more value, so we should add them all.
IDLebih banyak fitur berarti lebih banyak nilai, jadi kita harus menambah semuanya.
Designer (you)
ENThe premise is where it breaks. Features only add value if used — and unused features add clutter, which lowers value. So "more" doesn't reliably mean "better"; the right features do.
IDPremisnya yang patah. Fitur hanya menambah nilai kalau dipakai — dan fitur tak terpakai menambah kekacauan, yang menurunkan nilai. Jadi "lebih banyak" tidak selalu berarti "lebih baik"; fitur yang tepat yang begitu.
2Membantah dengan counterexample.
Anuj (PM)
ENSimpler always means better, right?
IDLebih sederhana selalu berarti lebih baik, kan?
Designer
ENNot always. Take the transfer flow — we once stripped it too far and users lost track of which account they were sending from. Over-simplifying can hide information people need. Simple, but not simpler than the task.
IDTidak selalu. Ambil flow transfer — kita pernah memangkasnya terlalu jauh dan user kehilangan jejak akun mana yang mereka pakai mengirim. Terlalu menyederhanakan bisa menyembunyikan info yang orang butuhkan. Sederhana, tapi tidak lebih sederhana dari tugasnya.
3Membantah sebab-akibat keliru.
Avril (Stakeholder)
ENSessions dropped after the redesign, so the redesign hurt us.
IDSesi turun setelah redesign, jadi redesign itu merugikan kita.
Designer
ENThat mixes up correlation and cause. Sessions dropped because users now finish faster — fewer sessions, but more completed tasks per session. The metric fell for a good reason, not a bad one.
IDItu mencampuradukkan korelasi dan sebab. Sesi turun karena user kini selesai lebih cepat — sesi lebih sedikit, tapi lebih banyak tugas tuntas per sesi. Metriknya turun karena alasan baik, bukan buruk.
4Membantah appeal to popularity.
Iksan (Designer)
ENEvery big app uses a bottom tab bar, so it must be right for us.
IDSetiap aplikasi besar memakai tab bar bawah, jadi itu pasti tepat untuk kita.
Designer
ENPopularity isn't proof of fit. Those apps have five top-level areas; we have two. Copying their structure would leave us with three empty tabs. What's right for them can be wrong for us.
IDPopularitas bukan bukti kecocokan. Aplikasi itu punya lima area utama; kita punya dua. Menyalin struktur mereka akan menyisakan tiga tab kosong. Yang tepat bagi mereka bisa salah bagi kita.
5Membantah false dilemma.
Anuj (PM)
ENIt's either ship fast or ship polished — pick one.
IDIni pilihan antara rilis cepat atau rilis rapi — pilih satu.
Designer
ENThat's a false choice. We can ship the core polished and fast by cutting scope, not quality. The real lever is how much we ship, not how good it is. There's a third option you're skipping.
IDItu pilihan palsu. Kita bisa merilis inti yang rapi sekaligus cepat dengan memangkas cakupan, bukan kualitas. Tuas sebenarnya adalah seberapa banyak yang kita rilis, bukan seberapa bagusnya. Ada opsi ketiga yang Anda lewati.

Berdasarkan Jenis Tindak Tutur (Searle)

Klasifikasi klasik tindak tutur menurut John Searle: asertif (menyatakan kebenaran), direktif (membuat lawan bicara bertindak), komisif (mengikat diri sendiri), ekspresif (mengungkap perasaan), dan deklaratif (mengubah realitas lewat ucapan). Kerangka fundamental untuk memahami apa yang sesungguhnya dilakukan sebuah kalimat.

Asertif

Assertive

Tujuan: mengikat pembicara pada kebenaran sebuah proposisi — menyatakan, melaporkan, menyimpulkan.

1Melaporkan status ke PM.
Designer (you)
ENThe checkout flow is complete and in review. All five screens are done, and the edge states are handled.
IDFlow checkout sudah selesai dan sedang direview. Kelima layar rampung, dan edge state-nya sudah ditangani.
Anuj (PM)
ENGreat, I'll update the board.
IDBagus, saya akan perbarui board-nya.
2Menyatakan temuan riset sebagai klaim.
Designer
ENI'm confident the OTP screen is the main drop-off point. The funnel and the session recordings both point to it.
IDSaya yakin layar OTP adalah titik drop-off utama. Funnel dan rekaman sesi sama-sama menunjuk ke sana.
Avril (Stakeholder)
ENThen that's where we focus.
IDKalau begitu di situ kita fokus.
3Menyimpulkan sebuah analisis.
Client
ENWhat's your read on the audit?
IDBagaimana pembacaan Anda soal auditnya?
Designer
ENMy conclusion is that the app is usable but not yet accessible. Sighted users do fine; screen-reader users hit three blockers. That's the gap.
IDKesimpulan saya, aplikasi ini bisa dipakai tapi belum aksesibel. User awas baik-baik saja; pengguna screen-reader menemui tiga penghambat. Itu celahnya.
4Menyatakan fakta teknis.
Bhaveen (Engineer)
ENDoes the design assume the balance is always available?
IDApakah desainnya mengasumsikan saldo selalu tersedia?
Designer
ENNo — the design accounts for a loading state and a failed-fetch state as well. Both are specced in the file.
IDTidak — desainnya memperhitungkan loading state dan failed-fetch state juga. Keduanya sudah dispesifikasikan di file.
5Menegaskan posisi sebagai klaim yang bisa dipertanggungjawabkan.
Avril (Stakeholder)
ENCan you stand behind the recommendation?
IDBisakah Anda mempertanggungjawabkan rekomendasinya?
Designer
ENI stand behind it fully. Every claim in it is backed by test data, and I've noted where the evidence is thinner so nothing is overstated.
IDSaya mempertanggungjawabkannya sepenuhnya. Setiap klaim di dalamnya didukung data tes, dan saya menandai di mana buktinya lebih tipis agar tidak ada yang dilebih-lebihkan.

1Mengarahkan tindakan engineer.

IDTolong ganti padding hardcoded dengan spacing token di layar konfirmasi sebelum handoff.
Bhaveen (Engineer)

IDAkan saya kerjakan sebelum hari ini berakhir.
2Bertanya untuk memicu tindakan.

IDBisakah Anda kirim teks legal final sebelum Kamis supaya saya bisa mengunci layar syarat?
Client
ENYes, I'll have it to you by then.
IDYa, akan saya kirimkan sebelum itu.
3Menyarankan langkah ke junior.
Inas (Junior Designer)
ENThe empty state still feels flat.
IDEmpty state-nya masih terasa datar.
Designer
ENTry adding a single clear action button and one line of guiding text. Give the user a first step, and it'll come alive.
IDCoba tambahkan satu tombol aksi yang jelas dan satu baris teks pemandu. Beri user langkah pertama, dan itu akan hidup.
4Mengarahkan fokus rapat.
Designer
ENLet's park the color debate and decide the flow first — we can't move without that.
IDAyo tunda dulu debat warna dan putuskan flow-nya lebih dulu — kita tidak bisa maju tanpa itu.
Anuj (PM)
ENAgreed, flow first.
IDSetuju, flow dulu.
5Meminta keputusan langsung.
Designer
ENI need you to pick between A and B today so development isn't blocked. Which one?
IDSaya butuh Anda memilih antara A dan B hari ini supaya development tidak terhambat. Yang mana?
Avril (Stakeholder)
ENGo with B.
IDPakai B.

4Berkomitmen memperbaiki kesalahan sendiri.

IDSpec yang saya pakai membangun ternyata versi lama.

IDSaya ingin ringkasan tertulis atas keputusan hari ini.
Designer

IDAkan saya edarkan sebelum besok pagi, lengkap dengan penanggung jawab dan tanggal tiap item. Anda akan menerimanya sebelum rapat berikutnya.

IDSaya minta maaf soal itu — keterlambatannya dari saya, dan saya paham itu memengaruhi perencanaan Anda. Saya sudah menata ulang jadwal saya agar tidak terulang.

Inas (Junior Designer)
